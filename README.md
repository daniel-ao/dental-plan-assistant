# 🦷 DentaPlan AI: dental treatment plan assistant

The dentist **dictates** a treatment plan. The assistant **builds a staged plan** (stages, intervals and prices from the clinic price list), **returns a PDF**, **asks clarifying questions**, and **regenerates the PDF** with the answers. Voice or text corrections create new versions. Download and sending stay locked until the dentist **explicitly approves** a version.

**Live demo:** https://daniel-ao.github.io/dental-plan-assistant/  ·  **CI:** GitHub Actions (tests, build and Pages deploy)

> *From clinical conversation to patient-ready treatment plan: the AI handles the admin work and the dentist stays in control.*

## Acceptance criteria (course build challenge)

| # | Criterion | Status | How |
|---|-----------|--------|-----|
| 1 | Understands voice | ✅ | Browser Web Speech API (EN/FR), live transcript you can edit, and voice corrections. You can also type or paste. |
| 2 | Asks clarifying questions | ✅ | Prioritised questions: implant system, discount %, ranges ("2–3 implants"), sedation, dictated price vs price list, conflicting prices, crown/implant count mismatch, missing intervals, items not in the price list, contradictions, and suspicious instructions |
| 3 | Generates a PDF | ✅ | Branded PDF made with jsPDF: patient and dentist details, stages with timing, teeth, qty, unit price, discount, subtotals, total, open-questions box, X-ray pages and a DRAFT watermark |
| 4 | Regenerates the PDF with the answers | ✅ | Each answer or correction produces a new version (v1, v2, v3 and so on) with a diff, kept in the version history |

Sample outputs (client Patient 1): [`samples/patient1_v1_before_questions.pdf`](samples/patient1_v1_before_questions.pdf) → [`samples/patient1_v2_after_answers.pdf`](samples/patient1_v2_after_answers.pdf) → [`samples/patient1_v3_approved.pdf`](samples/patient1_v3_approved.pdf)

## Demo in 60 seconds
1. Open the live demo and pick **Load a sample dictation → Patient 1**, or press **Record** and speak.
2. **Build plan & PDF** gives you v1 with its open questions listed in the PDF.
3. Answer the questions (implant system, sedation, discount, intervals…) and click **Apply answers & regenerate PDF** to get v2.
4. Type or say a correction, for example *"Change the price of the implant to €800. Add a dental radiograph to stage 1."* This gives v3, and the diff is shown.
5. **Approve v3**. This unlocks **Download PDF** and **Send to patient**.

## Stack
Static, client-only web app: HTML, CSS and vanilla ES modules. No backend, and patient data never leaves the browser.
- **Voice:** Web Speech API · **Extraction/planning:** deterministic rule-based engine over the clinic price list (208 items, generated from the `.xlsx`) · **PDF:** jsPDF + jspdf-autotable (vendored) · **Tests:** `node --test` · **CI/CD:** GitHub Actions → GitHub Pages
- Why deterministic rather than an LLM for the POC: there are no API keys to manage, results are reproducible, and the engine **cannot invent prices**. The production plan puts an LLM behind the same interface, with outputs constrained to catalog IDs (see the architecture doc).

## Repository layout
```
index.html            UI (Dictate → Clarify → Review PDF → Approve)
src/app.js            Orchestrator: state, versions, approval gate, delivery
src/engine/extract.js Clinical extraction agent (stages, items, teeth, qty, prices, discounts)
src/engine/plan.js    Planning + validation/questioning agents
src/engine/revise.js  Revision agent (natural-language corrections → field-level patches)
src/engine/guard.js   Prompt-injection / input guard
src/pdf.js            Document generation agent
src/glance.js         Page-one data for the PDF (tooth charts, stage colours, timeline, cost shares)
src/catalog.js        Price list (generated by scripts/build_catalog.py from data/*.xlsx)
data/                 Client inputs: price list + 5 dentist notes
tests/                Unit tests (all 5 client notes, pricing integrity, revisions, injection)
docs/                 Architecture, design system, security, user guide, acceptance, decisions
samples/              Before/after PDFs and screenshots
```

## Limits of the POC
No authentication or server storage: versions live in the browser session. "Send to patient" downloads the approved PDF and opens a pre-filled email. Images are attached to the PDF manually, and no X-ray interpretation is done. Extraction rules are tuned to the client's notes and price list.
